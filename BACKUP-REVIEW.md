# Opt-in structured record backup, review notes

Manual per-module backup, off by default. No opening-time network traffic, uploads or preselected choices. Mood and unfinished birth drafts require separate selection. A user previews both copies and confirms every upload, restore and deletion. Server revision checks block concurrent/stale overwrites; successful uploads never remove the phone copy. Restore refuses to replace a differing local copy. Unknown schemas and tombstones cannot restore. Account and journey ownership are checked by the backend; in-flight client operations bind to the original session. Shared demo uploads are refused.

Scope: structured health, first-visit registration (excluding MCP image references), Rh, danger log, birth, growth, vaccine, BP, sugar, high-risk and follow-up modules, plus separately selected mood and birth draft. No sessions, credentials, original files, vault files, GPS, audio or generic caches. Data export includes backed-up modules; account deletion removes payloads and tombstones. Existing backend RLS/default-grant protection applies to the new table before serving requests. This is server-readable app backup, not end-to-end encryption or provider disaster recovery.

Limits: manual only, not automatic continuous sync. Stable identity is journey+module, with one replaceable version and tombstone. There is no item-level cross-device merge, revision history or restore-overwrite button. Uploading a local collection explicitly replaces that module's server snapshot only at the previewed revision. Data deleted locally is not silently uploaded as deletion; deleting a server copy is a separate confirmed action. No new-account migration, whole-server backup or retention guarantee. Capacity must be monitored before real use. No paid plan or automatic real-record migration is included.
